# Nukkia Health v3 implementation

User selected implementation in the existing Nukkia app from the October 1 v3
blueprint and companion build pack. Reuse the existing brand workspace,
tenant/owner-scoped persistence and optimistic cloud revision checks.

Current foundation: React/TanStack/Supabase app, existing content studio and
local video renderer, authenticated workspace persistence. Baseline typecheck
passed; 446 existing tests passed. No qualified health policy, reviewer, input
screening, owned-twin provider, consent ledger, fenced paid job admission or
exact-package release authority is present. Existing generic marketing tools
are not a qualified health production pipeline.

First coherent build follows the pack's synthetic-first requirement: a Health
studio within Content, full proposed 48-template catalog, supported video preset
matrix, three explicitly deterministic text-card concepts, editable 1–12 scenes
(add/duplicate/split/merge/reorder/delete/script/timing), revisioned undo/redo,
saved drafts and local playable animatics. No uploads, external inference,
patient data, production render, export, publication or email sending. Preview
scripts contain fictional placeholders; they do not claim reviewed facts.

Production authority must be server-owned. This prototype has no production
API or release path; client draft JSON cannot grant consent, verify a credential,
activate policy or approve release.
Actual cost, performance, automation percentage and qualified presets remain
unmeasured. Catalog/preset counts describe the specification, not availability.

Acceptance: catalog 24 videos + 12 images + 6 carousels + 6 email drafts;
330 proposed baseline video presets / 156 beta presets / 13 twin-eligible
structures; three distinct editable preview approaches; timing and scene limits
block impossible animatics; revision conflicts reject stale mutations; undo/redo
and reload preserve exact drafts; existing content and owner boundaries pass
regressions. Independent review and build/typecheck/tests before handoff.

Remaining build stages retain the original sequence: server identity/policy;
quarantine and evidence; canonical briefs; fenced jobs/full-path budgets;
owned-twin enrollment/consent; qualified media rendering; three-option paid
production; exact-package review/delivery; non-video production/planning;
K01–K72 instrumentation and observed beta; catalog expansion/qualification.
The operator selected Brazil and medicine on October 2. Policy activation,
accountable reviewers and provider configuration remain outstanding. Do not promote prototype fields to trusted
authority or treat proposed QA counts as tests passed.
